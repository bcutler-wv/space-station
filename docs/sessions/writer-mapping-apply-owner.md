# Writer mapping apply owner, 0.105.0

The 0.104 fixed container wrapper, nine-name transfer and Compose policy passed all 29 jobs in exact-commit Ubuntu run `41999991103` at `6976fc03cd35e6176aab3ea36090f22da9684e41`, with Astra acceptance. This 0.105 source adds an uncalled mapping-only lock lifecycle, an owned stage for the exact prior and candidate public PEM trees, and an injected execution owner core. Its own Ubuntu regression remains pending.

The owner captures the nine external approval fields before I/O, checks the original create and role files, original CA and approved writer PEM against the sealed mapping intent, and creates a fresh same-call binding. It refuses a prior offline consumed binding or retained lock. The lock latches binding, transfer and apply attempts before I/O, with append/fsync uncertainty retaining the lock. Preflight failure retention applies only before a binding attempt. Both scripted phases require a completed owner fence before a result can be accepted. The exact transfer and consumer text, original container IDs, public-stage inodes and original inputs are checked through owned cleanup. Release requires normal callback return and final lock ownership, in addition to cleanup confirmation; a physical lock may already be absent after an ambiguous release, while the consumed binding still prevents replay.

The stage contains only the original prior public PEMs and candidate CA/writer public PEM. It records attempted creation separately from captured inodes and cleans only original owned objects. It reads no candidate private key and does not prove signer-key possession. The accepted wrapper already connects the fixed SDK sender and CAS adapter, but this owner has no production Docker adapter or host CLI. Local scripted tests do not prove Docker create/inspect/start, actual mapping PUT, PG CAS effects, hidden-resource completeness, fingerprint recording or readiness. Those require later separately reviewed runtime gates. No new dependency or product rule changed.
