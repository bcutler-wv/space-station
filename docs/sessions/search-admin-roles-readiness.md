# Disposable admin-role database readiness

Run `41796942107` reached the preexisting admin-role fixture's first migration while PostgreSQL reported that database `station` did not exist. Its Unix-socket `pg_isready` predicate reported only server readiness, not a successful connection to that database. [PostgreSQL 16's official utility documentation](https://www.postgresql.org/docs/16/app-pg-isready.html) says correct database credentials are unnecessary to obtain server status. The [official PostgreSQL Docker entrypoint](https://raw.githubusercontent.com/docker-library/postgres/master/docker-entrypoint.sh) starts a temporary socket-only server before creating `POSTGRES_DB` and later starts the final server; the [pgvector v0.8.7 Dockerfile](https://github.com/pgvector/pgvector/blob/v0.8.7/Dockerfile) inherits the official `postgres:16-bookworm` image for this fixture. This source sequence makes a premature readiness result plausible; the failed run did not retain an inner server trace identifying the exact interleaving.

Version 0.89.1 changes only this disposable gate. Its fixed probe now runs `SELECT 1` as `station` against database `station` at 127.0.0.1:5432 inside the container. It uses the existing container password internally, suppresses probe output, demands exactly `1`, and retains 30 attempts with the original one-second gap. No migration retries or permission assertions change. A local deterministic shell test proves socket-only and absent-database responses do not authorize migration, then proves a valid response does. The exact-commit Ubuntu gate and Astra review remain required.
