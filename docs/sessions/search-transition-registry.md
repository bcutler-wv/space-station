# Disabled search transition registry

Version 0.45.0 adds the database and pure manifest foundation for explicit search generation transitions. Both publication and serving remain forbidden by SQL constraints. No engine request, certificate creation, credential provisioning or live search path is introduced.

Each generation permanently reserves its physical index, role names and certificate principals. History records nullable public evidence without inventing it during upgrade. A durable operation record has one owner and starts armed; uncertain outcomes cannot permit advancement. Control updates use bounded transactions, complete expected-state comparison and exactly one revision increment. SQL guards preserve identity across stages and enforce initial states. The older disabled-only helper remains compatible with unregistered intents while rejecting P2 state.

Astra review corrected a UUID validator, direct-SQL state bypasses and a regression test that could have been masked by a duplicate key. The final full local check passed 110 tests. Six PostgreSQL 15 suites passed, covering fresh state, old and new upgrades, invalid-upgrade rollback, concurrent dispatch and unchanged disabled gates. Independent rereview passed fresh and upgrade suites plus 13 additional SQL probes. PostgreSQL 16 and Compose acceptance remain pending the new Ubuntu run.

The product contract now requires immutable generation-specific identities and complete retained history with exact physical presence. These clarify the planned runtime transition, rather than enabling it. The manifest denies above 512 rows or 256 KiB; overflow does not truncate history. Offline signing, hidden-role observation, limited admin database access, retained bootstrap and uncertain-request recovery require separately reviewed work.
