# Writer-mapping delivery gate

Version 0.107.0 adds a disposable-only, two-UID matrix for fixed mapping execution. Each independent project starts with one healthy create, writer-role preparation and delivery, then one healthy mapping preparation. The mapping-preparation fixture returns its already checked canonical proposal before its separate replay test retains a failed lock; this new path never adopts or removes that lock. The untouched fixed host CLI and image are the positive control. Four fresh projects per UID exercise pre-start evidence replacement and original SDK lost-return, false-ack and held-response behavior through test-only derived images.

The positive fixture requires `writer_attested` at R+5, a `response_confirmed` mapping dispatch, exact new mapping under the complete Security comparator, and unchanged raw prior registry, indexes, roles, mappings and public evidence. Its internal five CAS results and PUT count are inferred from the reviewed fixed code and final state. Prestart rejects before the apply container starts, with the original R unchanged and no mapping PUT or CAS. The other three measured negative fixtures require the first three original CAS returns through `sent_unknown` before a real mapping PUT, with one producer and Connection attempt. A genuine original 201 is checked before a return is discarded or replaced with a false 200; the held case requires original abort and response closure. A fresh restricted R+3 snapshot at PUT distinguishes that ordering from final-state inference. No uncertain project becomes a later positive baseline.

The gate records finite Docker Engine/API/Compose, OpenSearch/Security/SDK versions and created-container network shapes, and checks owned teardown before forwarding closed summaries. Original private logs, credential and generated-key markers are scanned after teardown output is captured and before private deletion on success or failure. The ten new Ubuntu jobs and full exact-commit workflow remain pending. Local tests and daemon-free Compose renders do not establish actual Docker mapping delivery. Certificate fingerprint recording, query mapping, publication and serving remain separate.
