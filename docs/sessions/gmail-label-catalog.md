# Complete Gmail label catalog

Version 0.32.0 of Gmail sync persists every label in its bounded provider catalog, including labels attached to no imported message. Empty labels receive account-local UUIDs and become available to the existing verified action-options API. Repeated sync and renames preserve those IDs; equal provider references in different accounts remain separate.

The provider read precedes one atomic catalog transaction. Account, sync-state and setup locks protect the credential generation, lease generation and configured origin. Upserts use batches of 100. Current-label reads are bounded by the existing 10,000-label provider limit; historical cleanup remains in the database, under three-second statement and 750 ms lock deadlines. The final database operation checks wall-clock lease validity after the event insertion. Cancellation or a failed fence rolls back the catalog and event together.

A vanished label still referenced by an item retains its UUID with an unresolved empty name, so privacy evaluation denies derived indexing and AI use. A vanished unreferenced label is removed; reappearance may give it a new local UUID. Unchanged catalogs emit no change event. Extremely large historical cleanup can time out and retry without publishing a partial catalog. ADR 0008 records these behavior details; DATA_MODEL already required empty provider labels in account lists.
