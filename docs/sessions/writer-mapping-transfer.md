# Writer mapping preparation transfer

Version 0.96.0 adds a fixed, uncalled transfer CLI and networkless Compose service plus an exact UID-1000 read-job service policy. The transfer checks original create/role intent and consumed binding links, a fixed canonical invocation and its transported SHA consistency, and the original host file/parent/public inventories. It copies only the fixed transition password, four original evidence files, invocation, and public CA/writer PEM to an exclusive input volume. Original source ownership remains the host UID 1000 or 1001; the copied tree is UID/GID 1000 with 0700 directories and 0400 files. The public stage mount uses `.cache/search-writer-mapping-prepare-public/<invocation>` so the public helper's separate scratch stays empty. No candidate private key, query PEM, CA signing key or signer tree is mounted into the read job.

The mapping-specific rendered and effective-container validators check the fixed two-service commands, mounts, networks and resource limits. The transfer is `network_mode:none`; the reader is restricted to `search_admin_db` and `search_internal` with only its copied input, existing admin certificate and bootstrap state volumes. Local real-file checks and daemon-free Compose renders for both host UID values do not prove actual container policy or live PG/OpenSearch behavior.
