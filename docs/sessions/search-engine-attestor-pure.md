# Search attestor pure handoff (E0c3a)

The attestor's pure handoff accepts a complete, ready verifier snapshot and an owner-generated invocation UUID. It canonicalizes every raw field, ordered row array, fixed verifier identity, and keyed six-digit timestamp sidecar before hashing a versioned envelope. It separately derives the expected generation inventory and public certificate filenames. A prepared manifest is accepted only when the full re-derived manifest matches; a matching raw digest alone cannot approve a changed inventory or file list.

The pure engine comparison first requires a strict primitive expected-inventory envelope, then the complete expected security roles and mappings, the exact physical index namespace, bound UUIDs, immutable profiles, and empty aliases. A malformed presence value cannot remove a physical-index obligation. Clean abandoned generations require absence and contribute no certificate filename. All inputs are bounded and unsupported values, callbacks, malformed timestamp evidence, or non-ready registry states fail closed.

This module performs no I/O and neither enrolls a generation nor resolves uncertain external dispatch. Its comparison is not an atomic engine snapshot. Command orchestration, public certificate delivery, and runtime serving or publication gates remain separate reviewed work; both SQL gates remain false.

Source accepted after independent Astra review for 0.59.0. Review corrected unsafe own-key copying, descriptor validation at the owner OID boundary and coercible expected-presence values that could otherwise omit a physical-index obligation. Eight focused tests and the full local check (154 tests, lint, typecheck, build, color and license checks) passed. The dedicated suite is wired into Ubuntu scaffold CI; its remote run remains pending. Raw evidence, expected inventory and manifest each have a separate 256 KiB bound. The comparison imposes a conservative 2 MiB canonical observation limit and fails rather than truncating larger evidence.
