# Private mail reader backend

M1 provides owner-only, account or Orbit-scoped conversation pages, thread message metadata pages, label lists, literal subject search, a separate item body, and private attachment downloads. The endpoints are `/api/mail/conversations`, `/api/mail/threads/:threadId/messages`, `/api/mail/labels`, `/api/mail/items/:itemId/body`, and `/api/mail/items/:itemId/attachments/:attachmentId/download`. Account and Orbit selectors are exclusive on list routes. Thread and item routes require the account ID and accept an optional Orbit ID. IDs are Station UUIDs, never provider IDs or paths.

The mail navigation slice adds `/api/mail/context`: a bounded owner-only list of configured Orbit names and color slots plus account IDs, Orbit membership, email address, provider, and reconnect state. It has no provider identifiers, credentials, message counts, or routing-management controls. The endpoint uses the same read-only transaction deadlines and same-origin guard as the reader routes.

Conversation summaries use only live items visible in the requested scope. A label filter selects matching items for the conversation list and summary; opening a conversation shows all live account/Orbit messages. Subject search is a case-insensitive literal substring, including `%` and `_`. Signed keyset cursors bind scope and filters; activity is descending with nulls last and thread UUID as tie breaker. Message pages use ascending millisecond-truncated activity with nulls last and item UUID as tie breaker. Pages hold at most 30 records and 512 KiB. Every reader database stage uses a read-only transaction with a three-second statement timeout and 750-millisecond lock timeout, including Orbit label scans and thread sorts. Blob I/O starts after the database transaction closes. Account label lists include empty labels; Orbit lists show labels attached to live items in that Orbit, including routed items.

Body text retains the parser's 4 MiB bound and HTML has a 1 MiB bound. One body response has a 32 MiB aggregate JSON cap, including worst-case escaping of supported text and HTML. Ingested HTML remains untrusted. An incompatible policy version, missing/corrupt blob, or mismatched image references produces an unavailable state. The response contains only opaque image reference IDs, not remote sources. The later mail view must re-sanitize with DOMPurify, use a sandboxed iframe, and add the planned image proxy before showing HTML images. Attachment downloads are at most 8 MiB and always attachment/octet-stream with nosniff. Missing or symlinked files produce a safe error.

Reader GETs are ordinary authenticated user activity and renew idle expiry. Sync progress/EventSource reads remain passive. Before any automatic SSE-driven reader refetch is added, implement an explicit passive read mode with full owner authorization or present a manual update prompt. Background refetch must not silently extend idle expiry.

The backend performs no provider request, read-state update, index operation or AI policy check. Owner source reading remains available under no-index and no-AI rules. The browser mail view, proxy and provider actions remain separate M1 work.
