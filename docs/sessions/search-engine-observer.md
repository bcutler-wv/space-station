# Fixed engine observation

Version 0.58.0 adds an independently Astra-reviewed admin-TLS observer exposing only `observe` and `close`. Nine fixed sequential GETs check the pinned engine version, health, physical namespace, namespace resolution, aliases, full role and mapping collections, security configuration and action groups. It returns bounded physical and security evidence for a later registry comparison. It cannot create, repair, enroll or publish a generation, and both SQL search gates remain false.

The shared SDK stream wrapper keeps existing callers' strict status handling. Only the fixed alias lookup can examine a bounded 404 body. Per-request deadlines remain active through body decoding; the observer also enforces an overall deadline and counts actual received bytes. Forbidden, malformed, ambiguous, closed-index and exhausted-budget responses fail with fixed errors. The admin certificate remains mutation-capable; the fixed facade is the code boundary.

Independent review corrected physical and resolve response validation, primitive status/attribute checks, fixture ownership preflights and isolated hidden-policy rejection. Focused TLS tests cover slow and oversized error streams, cancellation, malformed responses and fixed request paths. The disposable Ubuntu fixture uses the existing query identity in a private fixture-only tmpfs directory to exercise denial, and checks retained v1 UUID/profile plus full security restoration after owned-resource cleanup. No production credential staging or deployment was added.

Source review is accepted. Actual pinned OpenSearch namespace, absent-alias response, hidden collections, query denial and cleanup evidence remains pending in Ubuntu CI. Local fake TLS tests do not establish those engine behaviors. Complete DB/engine comparison, public-certificate verification and combined-container delivery remain subsequent work; sequential observations do not establish an atomic cross-system snapshot.
