# Writer mapping preparation runtime gate

Version 0.100.0 adds four disposable Ubuntu cases, one untouched host-CLI positive and one separate measured case for each supported host UID. It reuses the healthy create, writer-role proposal and positive writer-role delivery bootstrap. The prior create and role approval SHA values are latched before the role delivery run, then supplied independently to the mapping owner. The cases compare the full raw registry, microsecond timestamps, engine, E0b, admin and public evidence before and after preparing canonical pending bytes; a replay must leave those bytes and the consumed proposal unchanged, and retain a fresh failed-preflight lock.

The positive case's original IDs, operation order and request counts are inferred from its unchanged CLI and checked final state. The separate measured case wraps the actual fixed owner/adapter and passes each original Docker command through unchanged, recording create, original created inspect, completed owner fence and single captured-ID start for both services. A derived disposable image wraps the original SDK Connection request, preserves its receiver, arguments, callback, return and abort behavior, and records GET, HEAD and other methods. It must load, issue at least one real GET and no other method. The gate checks pending source/candidate, revision, original binding hashes and IDs, and the exact mapping request identity against independently retained create/role files. The transition database role is put in read-only default mode for that case; an authenticated UPDATE must fail, and its original bounded role configuration is compared byte-for-byte after checked reset in `finally`, including failure paths. A first failed owner method retains its finite phase/command/count trace across cleanup. Unchanged rows prove no successful write; the fixed source path supplies the no-CAS-attempt claim.

The established host scanner captures generated candidate-key markers without exposing key content. Private fixture output and teardown output are scanned before any finite success summary is forwarded; checked owned-resource teardown is required. The new source and local checks make no actual Docker claim. The 0.100.0 Ubuntu run and Astra runtime audit remain pending. This gate adds no mapping PUT, CAS, signer, fingerprint write, or readiness authority.
