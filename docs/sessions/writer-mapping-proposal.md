# Pure writer-mapping proposal evidence

Version 0.93.0 adds an uncalled pure constructor-issued projection and seal at one actual `writer_role_attested` predecessor R. Construction reuses the accepted role assessor for the original confirmed create and writer-role dispatches, their approvals and consumed bindings. It pins the complete original history, dispatch and microsecond timestamp sidecars and raw index, role and mapping collections. The fixed mapping contract derives one reserved writer principal in `users`, empty `backend_roles` and `hosts`, and a full-body SHA distinct from the stored dispatch metadata identity. Planned mapping IDs differ from all prior create and role dispatch, owner and invocation IDs. Cloned projections cannot be sealed as issued ones.

The pure public input contains the original and candidate CA PEM bytes and candidate writer PEM bytes as bounded canonical hex. It requires exact original-CA byte equality, both approved prior CA digests, the candidate writer digest, the reserved principal and the leaf's Node X.509 CN/fingerprint. This checks consistency of supplied bytes only: the future fixed read job must invoke and repeatedly recheck the accepted public helper to establish source acquisition, certificate chain, client-only purpose and fresh validity. A matching self-computed SHA does not authenticate operator approval; serialized assessment requires a separately approved SHA.

Seven pure comparisons cover R `writer_role_attested`, R+1 requested, R+2 armed, R+3 presend and postsend, R+4 response-confirmed, and R+5 `writer_attested`. They compare each independently supplied exact control successor timestamp, the immutable armed dispatch timestamp, the unchanged original create/role evidence and only the one new mapping in post states. Every accepted result is explicitly incomplete with `ready:false`; no CAS execution or original SDK acknowledgment is claimed. Candidate writer/query database fingerprints remain their original null values. The existing DB certificate operation writes both fingerprints together in a separate future approved transition; this slice writes neither.

Local tests use a public-only test certificate, complete legacy and retained-v2 source histories, an absent historical generation, original and successor microsecond timestamp changes, public/role/engine drift, forged reseals and accessor-bearing inputs.
