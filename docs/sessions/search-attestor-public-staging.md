# Owner-local public certificate staging

Version 0.63.0 is source accepted after independent Astra review and the shared monotonic deadline correction. Root's permission-enabled focused fixture passed all seven tests, and the full local check passed 154 tests plus lint, typecheck, build, color and license checks. Actual C4 container delivery remains pending. The prior 0.62.0 image build failed because Debian stopped serving the pinned OpenSSL package revision; that separate dependency repair is next.

The owner stages public certificates only after the preparation job is positively confirmed and supplies its captured manifest and global job-lock invocation UUID. The staging helper validates the offline manifest shape and derives its complete public path list. Fixed v1 PEMs come from the frozen `.cache/search-security` directory. Exact v2 PEMs come from the validated generation suffix under `.cache/search-generations`; absent generations contribute no path. The helper does not read or enumerate private key contents, call the signer, dispatch a job, or attest raw database evidence.

The owner process must be nonroot. Source and destination roots are canonical, owner-private directories. Source public PEMs are regular, single-link, owner-owned mode 0600 files read through bounded no-follow and nonblocking descriptors. The helper captures their bytes and metadata, validates CA and client certificates with the accepted C3b Node/OpenSSL checks using only captured bytes in owned scratch space, and writes one exclusively created invocation directory. Output directories are mode 0700 and public files mode 0400. File and directory sync precede a final exact inventory, source, output, and fresh validity recheck. Any failure returns a fixed diagnostic and leaves uncertain partial output for owner diagnosis.

Initial staging, including its final internal recheck, shares one 25-second monotonic deadline. The returned recheck operation can be called after later work and uses a fresh bounded deadline. Explicit cleanup also gets a fresh deadline and checks captured destination ancestors, directory and file identities, exact output inventory and captured bytes before removing anything. It does not depend on source certificates remaining available. Replacement or extra output paths are retained. Cleanup is one-shot; a partial cleanup failure is an incident for the later launcher. The launcher still owns preparation proof, lock lifetime, transfer and final container dispatch, and cleanup timing. Actual container delivery remains C4d.
