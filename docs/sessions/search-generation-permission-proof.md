# Disposable generation permission proof

Version 0.47.0 adds a disposable Ubuntu fixture for the pinned OpenSearch runtime. Two fake generations use distinct literal indexes, writer/query roles and client identities. The fixture checks complete admin role and mapping collections against reviewed upstream static roles plus exact expected application grants. Ordinary and hidden extra grants must be visible and independently rejected. Replaying the first generation's immutable policy must leave the second unchanged.

Positive checks cover strict external-version live documents followed by same-ID content-free fences. Negative checks cover cross-generation and v1 access, query writes, writer search, delete, administration and implicit index creation. The original index/get-only candidate failed actual pinned-image single-document writes because they enter the engine's bulk transport. The revised reviewed candidate adds only exact writer cluster `indices:data/write/bulk` and literal-index `indices:data/write/bulk[s]` alongside index/get. Disposable proof now tests own-index bulk INDEX/CREATE effects and forbidden foreign, query, DELETE, UPDATE and missing-index bulk effects. A raw writer credential can potentially use own-index bulk and ordinary version/CREATE writes; future application strict-external dispatch is not a raw-credential engine fence.

The optional fixture container mounts only selected identities read-only on the internal search network, with bounded resources and no published port. No private CA key, application credentials or database access is added. It reuses the existing official SDK streaming deadline and response caps. The gate checks actual container isolation and removes disposable resources.

Astra review required independent rejection of observed extra roles and mappings and positive external-version live-to-fence assertions. Both corrections passed rereview. The full local check passed 110 tests; comparator, container-boundary, lint and syntax checks passed. Ubuntu run `39828157358` at `ee14e63` passed container isolation, complete ordinary/hidden role observation and rejection, and immutable policy replay, then failed the positive writer operation with HTTP 403. The engine log identifies missing cluster action `indices:data/write/bulk`, which its single-document path uses internally. All four other jobs passed. The exact-action repair is source-only until its own pinned Ubuntu rerun succeeds; no live publisher, query consumer or admin transition is included, and M2 remains incomplete.

Version 0.49.0 records this explicit permission-contract correction. Writer dispatch identities now include the exact cluster and index action arrays; identities for other operations remain unchanged. Every control-locked transition checks stored intents for both its current and source v2 generations. Old writer evidence therefore blocks settlement, later stage advancement and reuse as a rotation source. Existing immutable rows are never rewritten to claim the new permissions; mismatches require explicit operator resolution. The legacy-v1 source has no v2 dispatch evidence.

Review found and corrected a bypass where an already-attested writer stage could otherwise carry old evidence into final attestation or a new reservation. Fresh PostgreSQL regressions cover those retained states and both terminal dispatch outcomes. The full local check passed 110 tests. The revised engine capability still requires its new Ubuntu proof.
