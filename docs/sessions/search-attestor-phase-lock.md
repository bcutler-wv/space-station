The owner-local `.job-operation.lock` remains exclusive across the existing verifier and transition inspectors, credential operations, and an attestor invocation. The lock creates the attestor invocation UUID; callers cannot supply one. Existing inspectors retain their single dispatch and completion API. Attestor uses a distinct fixed capability with ordered prepare, offline-transfer, and final-attestor phases.

The only permitted order is preflight, prepare dispatched/confirmed, transfer dispatched/confirmed, and attestor dispatched/confirmed. Each remote phase sets an in-memory attempted flag before writing a bounded phase record and syncing the lock file and parent directory. The caller receives dispatch permission only after that durable mark. An append or sync failure, process death, timeout, unknown remote result, or unconfirmed exit leaves the lock; no phase can be retried or adopted. The future owner adapter must positively verify the captured job and fixed result before calling confirmation. Transfer dispatch must precede volume creation, its first external mutation. The lock does not infer completion from a process exit, matching object, or elapsed time.

A wholly local pre-dispatch failure may release the original lock inode. After a confirmed prepare or transfer, a local stop releases it only after the caller confirms complete cleanup of owned artifacts and no outstanding remote job; it still returns an explicit incomplete failure. Final success requires confirmed final-attestor completion, the same cleanup confirmation, verified captured root and lock identity, and successful owned-lock release. A stale earlier-phase confirmation cannot release a newer attempted phase. Replacement lock or root paths are retained, and a callback that otherwise completed successfully fails with a fixed lock-release error if either identity was replaced. This protocol contains no timer, stale takeover, replay, recovery, Docker implementation, credential change, or enabled search gate.
