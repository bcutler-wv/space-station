# Writer-role delivery gate

Version 0.88.0 introduces a disposable-only two-UID actual-delivery matrix. A short existing bootstrap produces one original `uuid_bound` create and one read-only sealed writer-role proposal per isolated project. The matrix uses the unmodified fixed owner as its positive control, then separate projects for pre-start replacement, lost return, false acknowledgement and a held real transport response. Derived fault images replace copied runtime/core entry modules with test-only passthrough wrappers, retaining the pinned SDK's original call and abort handle; the production repository implementations are unchanged. No uncertain project is reset or used as a subsequent success baseline.

The fixture retains actual Engine, API, Compose and OpenSearch versions, stopped-container requested network shape, one completed pre-start fence per start, exact final registry/role evidence and finite SDK markers. It applies the existing strict canonical Security comparator to the new role, while prior raw roles and mappings must remain unchanged. The instrumented consumer pins the arm microtimestamp and checks it again at send and the fresh restricted R+3 pre-PUT snapshot without outputting the timestamp. The unmodified positive's R+5 result and five-step sequence follow its reviewed source and final state; instrumented cases record original CAS returns and an independent restricted R+3 snapshot at PUT. Neither is a direct observation of all five commits. The shared gate scans private output and checks owned teardown before forwarding a closed sanitized summary. These are source-level tests until the full exact-commit Ubuntu workflow passes and Astra audits its retained evidence. Both readiness gates remain false; mapping, principal and serving work is separate.

All ten delivery jobs in the first 0.88 Ubuntu run `41796942107` failed: both positive projects at owner and eight negative projects at phase evidence. This does not imply the whole workflow had completed. Those coarse checkpoints do not locate the delivery defect. Version 0.89.2 adds closed fixture-only traces for original instrumented owner methods and Docker command outcomes, saturated counts with an explicit overflow class, actual created-state category observations, and finer evidence checkpoints. The original positive CLI/image, policy checks, command results, assertions, timeout, scan and cleanup order are unchanged. The delivery cause and full runtime acceptance remain pending.
