# Writer-mapping proposal adapter

Version 0.99.0 connects the accepted local proposal owner to one fixed host CLI and a named Docker adapter branch. The CLI derives its repository from its script location, requires the host UID/GID declared by `APP_UID`/`APP_GID`, takes exactly seven nonsecret positional fields, and has a 510-second whole-command ceiling over the owner's 480-second bound. Its two prior approved SHA fields are externally supplied assertions of earlier approval, not an authentication service or permission to execute a mapping PUT.

For each fixed transfer/read phase, the adapter verifies the original project, credential and infrastructure context, renders the exact two-service policy, checks service and fixed-name absence, creates one container without build/pull/recreate, and inspects that original ID in a pristine created state. It then awaits the owner's completed original-source fence before one start of that same ID. Later inspections require original metadata, actual network IDs, terminal timestamps and exact bounded output. Checked cleanup removes only the original two IDs and input volume before the owner writes a canonical pending proposal. The transfer is networkless; the read job uses only the two existing internal networks and the existing transition credential through read-only code paths.

The fixed adapter's command-order fixture and both-UID daemon-free Compose render checks prove source behavior, not actual Docker Engine created-state shape, PostgreSQL/OpenSearch proposal delivery or runtime duration. A separate disposable Ubuntu gate and full 0.99 regression remain pending. This slice adds no mapping PUT, CAS, signer operation, certificate fingerprint write, or readiness change.

Source review kept the additional fixed-name reference checks mapping-only, preserving the older writer-role apply command path. The mapping branch also pins its first post-start `StartedAt` through terminal inspection, pins `FinishedAt` when first observed already exited, and requires terminal `Paused` and `Restarting` to be false. Scripted reached negatives exercise each condition; actual Engine behavior remains for the Ubuntu gate.
