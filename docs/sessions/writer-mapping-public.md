# Candidate writer public certificate capture

Version 0.92.0 adds an uncalled public-only reader for the candidate writer certificate. A fixed owner supplies the repository, current UID/GID, generation token and the offline signer's five-field **public** result. The reader derives `.cache/search-generations/<lowercase-token-suffix>/writer.pem` and `.cache/search-security/ca.pem`; it accepts no caller path or role selector. Narrow exports of the existing create-public bounded directory/file readers preserve their prior behavior while checking nofollow, regular-file, exact owner/mode/link count, original path and opened-handle inode, timestamps and bytes. The reader requires the signer directory's exact four filenames but opens only the two public PEMs. It validates the CA and writer leaf using the existing chain, CN, client-only purpose, validity and fingerprint checks, then rechecks the original files and their parents after the awaited OpenSSL call. Later rechecks use the original pinned bytes and fresh certificate validity. The fixed `.cache/search-writer-mapping-public` scratch directory must preexist with owner-private mode 0700; the helper does not accept an arbitrary scratch path.

Real-certificate local tests use the already reviewed offline signer, deny direct reading of both private keys while public capture succeeds, and exercise malformed signer fields, file/parent replacement, unsafe types, changed certificates and private scratch failure. Returned public bytes are copies, and metadata is frozen. These tests run in the scaffold; this version has no claimed Ubuntu result until the exact-commit workflow runs and Astra reviews it. The signer result only checks internal public consistency. A coherently replaced CA and signer result could still validate on first capture; a later operator-approved proposal must independently compare the original prior CA/public evidence and original role/create context. No private key is read, transferred or attested as possessed here. No signer call, database history fingerprint write, mapping approval, CAS, SDK send, Docker owner, live writer, publisher or readiness grant is enabled.

The certificate validator reuses the existing pinned OpenSSL and Node X.509 operations. [THIRD_PARTY.md](../../THIRD_PARTY.md) records their source, versions and Apache-2.0 provenance; no package dependency or upstream code was added in this slice.
