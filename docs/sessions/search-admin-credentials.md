# Stopped search administration credentials

Version 0.50.0 adds the Astra-reviewed explicit owner-local command creates, verifies or aborts pending initial credentials for the two restricted search database roles. It uses existing PostgreSQL `psql` and Node APIs without adding a dependency. No production command was run, and no search job, scheduler, engine identity or live search gate is enabled by this change.

Private installation metadata and independent password files are synced before database changes. A complete bundle is published with one directory rename after actual correct- and wrong-password checks on the same SCRAM endpoint. Retained verification audits existing permissions without granting or repairing them. The durable PostgreSQL system identifier survives ordinary container recreation; it does not distinguish physical clones or restores.

There is no atomic transaction spanning PostgreSQL and the filesystem. Roles can briefly have LOGIN before publication while jobs remain stopped. Every owner mutation has a durable in-flight marker. An unconfirmed Docker operation leaves that marker and requires independent owner diagnosis before recovery. Explicit abort verifies installation identity, disables the dedicated roles, terminates their sessions, clears their passwords and removes only owned pending material. Published bundles cannot be aborted. See [deployment and recovery](../DEPLOYMENT.md).

Review corrected bounded metadata reads, inherited libpq settings, HBA netmask checks, shutdown uncertainty, remote mutation ambiguity and missing-table detection in the audit-only path. The original effective privilege audit remains unchanged. Local PostgreSQL 15 fixtures passed staged and uncertain failures, explicit abort, retained verification, permission drift, wrong passwords and malformed files. The original restricted-role lifecycle regression and full local check passed, including 110 unit tests.

The separate Ubuntu PostgreSQL 16 gate exercises the actual Docker command in a disposable Compose project without a host database port. That gate passed in Ubuntu run `39837617714` at `e5bedde`, including actual correct/wrong-password authentication, retained read-only verification and published-bundle abort denial. The full workflow also succeeded, accepting this credential slice. Runtime credential delivery and rotation remain separate tasks.

## Stopped single-role rotation

The owner-only `rotate`, `finish-pending-rotation` and premutation `abort-pending-rotation` commands are implemented and Astra-reviewed in 0.53.0 for the verifier or transition role; actual Ubuntu PG16 proof remains pending. Both search SQL gates remain false. They share the global job lock and credential lock in that order. A target role's running or stopped Compose containers block rotation; the other role is never mutated by a rotation attempt. The selected role's private staged old/new files remain available through uncertain remote outcomes. `finish` always uses staged new, while abort is allowed only before `started` and any in-flight marker. Every remote owner mutation writes a synced marker binding operation, attempt, action, role and the actual captured PostgreSQL container ID. A subsequent finish requires independent removal of that exact old container ID, reattestation of the replacement installation and current other-role policy, then a new attempt. There is no reset-old branch or timed stale-marker takeover.

The recovery-only audit retains all registry, privilege, catalog, default ACL and false-gate checks from the ordinary audit. Its sole exception permits the selected target role to hold a SCRAM verifier while temporarily NOLOGIN; the other role must remain LOGIN with a SCRAM verifier. Ordinary audit and initial policy explicitly select normal mode, so a target NOLOGIN with a verifier is still rejected outside recovery. Local real PostgreSQL 15/SCRAM and fake process fixtures cover both-role rotation, old-password denial, pre-mutation abort, post-rename finish, two successive uncertain attempts tied to A then B container IDs, and pre-mutation grant/flag drift denial. The disposable PG16 Compose gate is wired but has not run yet; no local Docker success is claimed.

Independent review corrected asynchronous credential-lock lifetime, exact staged-file modes, recovery audit mode selection and the disposable replacement-container selection. Fresh owned PG15 testing and the full local check passed. The selected-target recovery audit is a narrow contract clarification; it adds no grants and leaves normal audit strict. The Ubuntu gate must still prove actual Docker uncertainty recovery, stopped-container denial, held sessions and fresh file binds before runtime acceptance.
