# Durable Gmail send backend

Version 0.27.0 implements explicit owner-triggered Gmail send and Sent reconciliation. A durable operation binds the client key to the draft, account, Orbit and revision, records audit intent, and freezes exact MIME bytes before one provider claim. Source attachments remain owned during preparation. Confirmed sends mark the draft sent and detach its source files; uncertain outcomes remain locked and never automatically resend. Status can be recovered by operation or draft ID.

Nodemailer 10.1.7 (MIT-0) generates bounded MIME using owned buffers, with filesystem and URL resolution disabled. Gmail-specific raw messages retain Bcc. The existing official Gmail SDK disables retries and rejected-token replay for send. Reconciliation checks a bounded complete candidate set, exact Message-ID and account evidence, and current credential generation. Missing or ambiguous Sent evidence never authorizes another send. Unknown MIME files remain retained pending an explicit resolution policy; confirmed files expire after 30 days.

Sol implemented the slice and Astra independently reviewed it. Review corrected resource allocation and handler limits, strict reply context, scope fences, orphan publication cleanup, terminal state and collector behavior. Independent review found and corrected unbounded credential database waits. All credential reads and writes now use short transactions with three-second statement and 750-millisecond lock deadlines; provider refresh runs outside transactions. A held-lock probe returned busy in 764 ms, and the route fixture proves the failure occurs during credential preparation after durable MIME publication. Audit documentation now describes the actual implemented actions.

Local lint, typecheck, 77 tests, build, color and license checks passed; the production dependency audit reported no vulnerabilities. Fresh PostgreSQL 15 authenticated HTTP/provider/filesystem tests covered compose and both reply paths, attachment freeze, double clicks, scope changes, MIME size, unknown outcomes, restart, reconciliation and crash cleanup. Astra independently verified committed intent/blob/claim before the provider callback and rejected wrong or duplicate Sent evidence without resending. Test databases were stopped. Fixtures use fake providers and example.com identities, not live Gmail delivery.

Ubuntu PostgreSQL 16/Compose and browser integration are wired and pending for this commit. Compose UI, unresolved-operation discovery, explicit archive/read/label actions and final M1 acceptance remain separate work. See [the send decision](../decisions/0011-durable-gmail-send.md).
