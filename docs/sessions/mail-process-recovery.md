# Mail process recovery fixtures

Version 0.33.0 adds an M1 reliability fixture that crosses real app and worker process boundaries. A separate loopback provider process keeps observations alive while workers or the app are terminated. The fixture uses the accepted Google SDK adapters, credential service, GmailSyncRunner, pg-boss, parser client/service/child path and private blob store. Production entrypoints contain no fixture controls.

Initial ingestion stops after the first item and cursor offset commit. History ingestion stops after an added item commits and the cursor advances to the tail page. The original queued job expires to failed with zero retries, matching production policy. A replacement worker consumes startup discovery and enqueues a distinct successor with the account singleton key; it resumes the saved cursor without duplicates or rereading the committed history item. The fixture shortens queue expiry to fifteen seconds, explicitly invokes queue maintenance, and advances the killed worker’s lease timestamp. It does not claim to exercise production’s full 900-second expiry timing.

A separate process tests lease denial while the first worker is demonstrably running with an unexpired lease, then takeover after controlled expiry. This isolates lease fencing from the stately queue’s serialization of simultaneous deliveries. A send test kills the app after the provider accepts MIME but before durable success. The same database, frozen blob and provider observations survive restart; authenticated discovery and explicit Sent reconciliation settle the operation with exactly one provider send. Only the stale-status timestamp is advanced to avoid a thirty-second wait.

A dedicated Ubuntu CI job uses a fresh PostgreSQL 16 database, real migration entrypoint and configured private volume. It uploads child logs and removes its disposable Compose stack on completion or failure. The local fixture uses actual parser processes; container resource limits and network isolation remain covered by the separate existing parser gate. Authenticated Node HTTP requests with trusted proxy headers are not the final TLS browser journey.
