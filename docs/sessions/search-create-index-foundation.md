# Create-index foundation

Version 0.67.0 is the first stopped source review toward a disabled P2 `create_index` transition. `assessCreateIndexEvidence()` accepts the existing complete, microsecond-bound raw registry snapshot from the fixed `station_search_transition` DB identity and the fixed admin observer's bounded result. The earlier ready attestor still requires `station_search_verifier`; neither predicate accepts a caller-selected role. Create evidence checks an exact expected revision, stage, transition, source and candidate identity, dispatch owner/state, both false gates, all prior registered index profiles including complete retired v2 history, clean abandoned absence, candidate absence before create or the exact new UUID/profile after create, and complete observed role/mapping collections. The fixed observer separately verifies engine identity, health, resolved physical names, alias absence, security configuration and action groups before returning that result. Directly supplying an arbitrary object to this pure predicate does not prove those upstream observations occurred; a future combined job must call the fixed observer and recheck the registry snapshot. No partial result is a readiness attestation.

Its discriminated result is either `create-evidence` with `phase: precreate|postcreate` and `ready:false`, or `create-evidence-rejected` with `ready:false`. It calls the unchanged complete-registry oracle for structural and historical dispatch checks but never asks that oracle to classify a partial stage as ready. This stop covers `disabled_intent` before arming and `create_requested` with `armed` before send or `sent_unknown` after the original send. It deliberately rejects `response_confirmed` and `uuid_bound`; a later reviewed owner slice must supply its own post-CAS evidence checks. Candidate role/mapping/certificate evidence is not invented from the reserved row. Clean abandoned earlier generations remain absent; unavailable or historically partial rows fail.

`createLiteralV2IndexOnce()` is an uncalled adapter, not an owner command. It accepts an already constructed official client index API, a validated literal v2 name, and no caller body or destination. It sends the exact frozen `createV2IndexBody()` once through the existing streamed 5-second, 32 KiB create-response cap with per-request `maxRetries:0`; only original `acknowledged:true`, `shards_acknowledged:true`, exact index response permits one 5-second, 128 KiB GET. The existing exact profile comparator rejects changed mappings/settings, aliases and malformed or mismatched UUID. The adapter returns only the UUID and neither retries nor adopts a remote result after a lost or false acknowledgement. There is no production caller, service, credential delivery, DB write, publication or serving path. The disposable existing engine fixture calls the adapter solely to prove actual pinned SDK response/readback shapes; it is not P2 dispatch evidence.

The installed official `@opensearch-project/opensearch` 3.9.0 dependency and Apache-2.0 provenance remain pinned in `packages/search/package.json`, `pnpm-lock.yaml` and `THIRD_PARTY.md`. [The official JS client guide](https://docs.opensearch.org/latest/clients/javascript/index/) documents `indices.create`; [Create Index](https://docs.opensearch.org/latest/api-reference/index-apis/create-index/) documents the two acknowledgement flags and that a timed-out acknowledgement may still leave an index. No dependency or lockfile changes were made. Actual Ubuntu API-shape proof and full workflow, then independent Astra review, are required before accepting this stop. M2 remains incomplete.
