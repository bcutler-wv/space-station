# Fixed writer-mapping consumer

Version 0.103.0 adds an uncalled copied-input reader and one-call mapping consumer core. The accepted 0.102.0 fixed CAS predecessor passed exact-commit Ubuntu run `41984006557` at `94ab191` with all 29 jobs and Astra review. The new slice's own Ubuntu regression is pending.

The reader requires one fixed UID-1000 root with exactly the mapping intent and consumed binding, four historical create/role files, transition password, complete prior-public tree and a separate candidate CA/writer public pair. It checks canonical bytes, original copied inodes and inventories, certificate chain, client purpose and freshness, then returns fresh copies and recheck closures. The complete prior public tree may include historical query certificates; the candidate tree contains no query certificate or private key. Copied bytes establish consistency, not operator approval or host source identity.

The core captures an independently supplied nine-field approval, execution invocation and expected database identity before input I/O. It requires the original `writer_role_attested` R baseline and seven exact pure mapping states, checks five fixed CAS successors against R through R+5, and latches six-digit timestamps from accepted CAS results. After `sent_unknown` it opens the constructor-issued fixed mapping sender, repeats the full presend fence after that await, and accepts only the original first-create acknowledgment plus exact post-state observation. Failures stop without retry or GET adoption. Candidate certificate fingerprints remain null in the registry and both search gates remain false.

Real-file/certificate and scripted tests verify this source boundary. They do not prove actual PostgreSQL commits, an OpenSearch PUT, host transfer/lock cleanup, or hidden-resource completeness. A separately reviewed same-invocation host owner and actual both-UID mapping-delivery gate are still required. No signer, fingerprint write, readiness, publication or serving path is added.
