# Explicit v1 index introduction

The installer issues a one-time v1 introduction grant only when both the search data and security-state volumes are empty. It syncs an exclusive first-initialization reservation and grant before publishing `phase=fresh`. Retained legacy `fresh` or `ready` state remains grantless. Partial state and unexpected files fail closed; neither engine absence nor a matching profile can repair it.

The ordinary `search-profile-bootstrap` reads state without write access. It verifies an existing exact profile, rejects a missing index, and compares the recorded index UUID when introduction completed. A separate `search-profile-introduce` service is outside the ordinary search profile. It requires the fresh grant and security readiness, observes a 404, syncs a permanent exclusive claim, sends one pinned SDK create request, then syncs a create-only UUID completion after acknowledged creation and exact readback. A timeout, conflict, partial response or failed readback leaves the claim incomplete and forbids automatic resend. The engine and private filesystem cannot commit atomically; repair or retirement needs a separately reviewed operator procedure.

This correction preserves the frozen v1 mapping, settings, roles and certificates. It adds no generation enrollment, publisher, serving route or live gate.
