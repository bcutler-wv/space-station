# Mail compose and reply

Version 0.28.0 adds compose and reply inside the live Mail frame. The editor shows its fixed sending account and optional Orbit, To/Cc/Bcc, subject, plain text and owned attachments. Server drafts have stable deep links and survive reload. Reply uses the validated destination and fixed conversation subject. A serialized revision queue orders autosave, attachment changes and explicit send; conflicts retain local text and require an explicit choice before leaving.

Drafts and unresolved sends are discoverable through bounded, account-selected pages. The discovery endpoint uses signed microsecond cursors and optionally narrows to an exact Orbit. Account-wide discovery includes that account's Orbit-scoped operations; opening uses the stored exact scope. A lost response checks the current send UUID, so an older failed operation cannot unlock a newer uncertain attempt. Reconciliation remains an explicit Sent read and never resends. These are documented clarifications in DESIGN, DATA_MODEL and decision 0011.

Sol implemented the slice and Astra reviewed the source and actual desktop light/mobile dark captures. Initial review corrected sender selection, routed reply scope, stale draft reopening, upload/autosave races, conflict navigation and hidden keyboard controls. Independent browser probes then exposed reconnect data loss, invisible attachments after failed-send recovery, and stale status responses reversing confirmed success. The fixes preserve the active editor on reconnect, restore authoritative draft and attachment state before unlocking, and reject obsolete status results. All three original probes passed unchanged after correction. Typing after a conflict keeps the conflict explanation visible.
