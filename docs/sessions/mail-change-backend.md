# Gmail message-change backend

Version 0.29.0 adds explicit one-message archive, mark read/unread and existing user-label changes. The owner request freezes the exact item/account/optional Orbit, revision, sequence, desired labels and idempotency key. A separate operation row and content-free audit intent precede provider calls. Bounded official SDK reads verify user-label type and absence of DRAFT; a final live scope/current-credential check claims one modify attempt. A failed or uncertain call after claim is never automatically repeated.

Exact-key status and bounded signed-cursor discovery recover operations after a lost response or reload. Explicit reconciliation reads current Gmail labels and checks current scope before and after I/O. Provider confirmation and later observed desired state remain distinct historical outcomes. Local synchronized labels and content are never overwritten by a partial provider response.

Sol implemented the bounded backend and Astra reviewed it. Review corrected credential refresh handling, key recovery, no-op behavior, same-item concurrency when sync advances during a held write, whole-handler bounds and live reconciliation scope checks. Pending, in-flight and unknown changes block another action across item sequences. A nonmatching unknown outcome remains blocked until reconciliation observes the desired state; later UI must explain manual Gmail repair without silently retrying. A zero-write observed no-op permits another explicit action.
