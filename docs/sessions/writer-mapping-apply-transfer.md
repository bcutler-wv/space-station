# Fixed writer-mapping execution transport

Version 0.104.0 adds an uncalled container wrapper, a networkless transfer and a two-service Compose render/effective policy. The prerequisite 0.103.0 consumer passed exact-commit Ubuntu run `41991173798` at `3b8d2f8079d6a077cd13ff5bf23e2e1a0843ceea`, all 29 jobs, with Astra acceptance. This slice's own Ubuntu regression is pending.

The transfer copies the approved mapping intent, consumed binding, four original create/role files, transition password, full historical prior-public tree and candidate CA/writer public pair into one fresh nine-name UID-1000 volume. It has no network and receives no candidate private key, CA signing key or signer tree. The copied SHA is consistency evidence, not approval; a future owner must supply the independent nine-field approval and a fresh same-invocation binding. The fixed wrapper accepts those nine fields plus execution invocation, project, database OID and system identifier before any input I/O. Its base Compose command has no authority and fails before acquisition; only a later trusted private command may append the exact thirteen values.

Rendered and effective policies require the fixed commands, mounts, names, users, networks, image target and resource limits. A later owner/adapter must inspect created containers before a completed original-source fence and captured-ID start, then prove actual running network IDs and checked cleanup. This version has no host owner, CLI or Docker adapter, new SDK or CAS behavior, fingerprint write or readiness grant. The uncalled container wrapper connects the accepted mapping sender, but local real-certificate and scripted tests do not establish a Docker or OpenSearch PUT result.
