# Writer-mapping proposal local owner

Version 0.98.0 joins the accepted read-only mapping proposal byte contract to fixed host-local file capture and persistence. It is uncalled by a production CLI or Docker adapter. The owner copies seven nonsecret caller fields before awaits: two independent, previously approved create/role intent SHAs and the existing five-field offline signer public result. It checks the four original create/role pending and consumed-binding files against those supplied SHAs, pins the original public CA and candidate writer PEM through the accepted public-only helper, and stages exactly two public PEMs. A separate fixed invocation carries those fields to the already reviewed networkless transfer contract.

The owner gives its injected trusted adapter one completed original-source fence per transfer/read start. It retains a private host baseline, checks original four-file inventories and created public-directory identities after awaited reads, and retains the original checked read-job response bytes through remote and local cleanup. It then exclusively writes a canonical 0400 pending proposal after a durable pending-attempt record. Checked no-attempt local cleanup permits normal lock release only after established public and host context is rechecked; uncertain partial local cleanup calls the mapping-only preflight-failure latch. An owned helper scratch is removed against its original cache-parent identity. A pending file still denies replay if an ambiguous release removes the lock. The new owner does not authenticate who supplied the earlier approval SHAs, prove private-key possession, record certificate fingerprints, approve or send a mapping PUT, perform CAS, or enable readiness.

Local real-file/scripted tests cover legacy and retained-v2 source evidence, original file/public drift, both pre-start callbacks, partial local creation and cleanup, lost phase return, partial pending replay, and original response-byte retention. Full Ubuntu regression of this source is pending. A separate fixed Docker adapter/CLI and disposable actual PG16/OpenSearch proposal gate must prove the host resource and create/inspect/start behavior before this flow is operational.
