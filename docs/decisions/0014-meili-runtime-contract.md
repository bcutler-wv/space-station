# Pinned private Meilisearch engine foundation

## Decision

Pin the official Community Edition Meilisearch 1.55.0 image at `getmeili/meilisearch:v1.55.0@sha256:ff546679970126f8822e15d1b6a06bfbff1f2ce2e43f810cfb5258012f92de5c` (Docker Hub multi-platform index digest) and the official ESM `meilisearch` JavaScript SDK 0.62.0. The tagged Community binary has SHA-256 `7e33f5889235f14290074a19a6d3574bd9b10fb2ee8731eabb7dafd0714b0513` on Linux amd64 and reports commit `420ff1362801adb58c938aec89700e8f7e32e566`. The Community source license is MIT; the separate Enterprise artifacts are not selected. The SDK installed license is MIT and its exact version is locked.

The engine runs in a private, internal Compose network with no host port. Its key is generated in `.cache/meilisearch.env`, mode 0600, separate from Station's master key and image-proxy key. Only the engine, one-shot bootstrap and disposable contract fixture receive it. The current app and worker do not join the search network or receive the key. The `search` profile leaves the existing app startup path unchanged while later source consumers are reviewed. The engine is nonroot with a private named volume, read-only root filesystem, capability drop, no-new-privileges, resource limits and disabled anonymous telemetry. A one-shot bootstrap verifies the exact version/commit and enables experimental `containsFilter`; failures stop bootstrap. Actual image compatibility and isolation require the Ubuntu Compose gate.

SDK operations have a five-second HTTP timeout through response-body consumption. The pinned SDK's custom HTTP hook enforces a one-MiB parsed-response cap and refuses redirects; that hook is marked deprecated upstream, so a future SDK upgrade must recheck the bound before replacement. Test settings and document writes wait for a terminal successful task with a 20-second bound **after** the enqueue request returns; the enqueue itself has the separate five-second HTTP bound. An enqueue receipt is not treated as completion. Error categories avoid logging credentials or provider data. The current fixture restricts result shape to IDs and 20 hits. No production query method, AST lowerer, source indexing, serving, policy grant or purge mechanism exists in this slice.

## Engine contract evidence and limits

Against the checksum-verified local Community binary and SDK, fake documents showed that `matchingStrategy: all` enforces two ordinary query words, while default-style `last` admits a red-only document for `red apple`. Negative words, negative phrases, negative-only queries, filter `NOT`, and same-index federated OR worked; federation deduplicated the same document. Federated queries reject a per-query `limit`; pagination belongs to `federation.limit` and `offset`. `CONTAINS` worked after explicit activation for substring values, including an address and punctuation. These are version-pinned observations, not authorization. An external scope must later be a validated nonempty structure compiled into every branch outside user Boolean input; a raw caller filter must never be accepted.

The engine silently ignores the eleventh unquoted word even with `matchingStrategy: all`. A quote around a whole eleven-word phrase behaved differently in the local probe, but mixed cases are not proven. The future AST lowerer cannot safely count query words by whitespace: the official Charabia tokenizer has language-specific segmentation, including CamelCase and German compounds. This task adds no approximate tokenizer or severe user-facing character cap. The next task must resolve that limit with the exact pinned tokenizer behavior or reject only proven unsupported forms before any live query is enabled. The fixture keeps the missing-eleventh-word result as a regression warning, not an accepted search result.

Full-text quotation preserves word order, not punctuation bytes: `"invoice.pdf"` also matched `invoice-pdf`, and a quoted backslash path matched a hyphen path. Structured `CONTAINS` is the intended literal-substring mechanism, subject to its experimental version pin. The engine matched typo and prefix examples but did not match query `running` to stored `run`; automatic stemming is deferred. Search docs now describe ordered-token phrases and remove the unproved stemming promise. No custom stemmer is added.

## Consequences

Do not expose the engine or use a parsed AST for live results until a later reviewed lowerer proves every supported Boolean branch, tokenizer bound, phrase/literal rule, scoped name resolution, response cutoff and failure behavior against this pinned engine. The later index writer must revalidate current source policy before publication and the later server must revalidate before serving; the fake fixture and transport cannot grant access.
