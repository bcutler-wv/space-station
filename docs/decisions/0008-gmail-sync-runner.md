# 0008: Durable Gmail ingestion checkpoints

Date: 2026-10-20

The M1 worker uses the accepted bounded Gmail read adapter and normalized mail page operation. It freezes the selected backfill cutoff and a profile history anchor in `sync_state.cursor` before listing. A cursor contains at most ten pending list IDs or a history page offset, never a full raw-message page. Each message and its next offset commit through `applyMailPage`, which fences the account credential generation, lease generation and sequence. No Gmail request or MIME parse runs inside that database transaction. A failed or duplicate job resumes from the persisted cursor. After a full scan, the worker catches up from the original anchor before marking the account ready.

The final message of a terminal list batch commits the move out of the full-scan phase in the same page transaction. A runner restarting from the older exhausted-batch cursor also recognizes it without relisting the first page. A job signal, process shutdown, or the runner's twelve-minute elapsed budget interrupts pacing and prevents returned provider or parser results from advancing a cursor; the runner releases only its own generation-fenced lease. This budget leaves room below the fifteen-minute queue expiry for bounded in-flight requests and cleanup.

An expired history cursor starts a new full scan with a new pre-list anchor and retains the original cutoff. The runner records the scan's starting mail-page sequence. Only after the list is fully enumerated does it tombstone retained in-window items whose `appliedSequence` did not advance during that scan. An interrupted scan never runs this deletion phase. Older retained items stay outside the reconciliation deletion set, but history can still update or delete them. For an all-mail scan, items without an internal date are included in deletion checks. History pagination keeps the original `startHistoryId` until the terminal page supplies the replacement ID.

Discovery requires the confirmed current origin, valid privacy setup and a saved backfill. A per-account request slot persists one-second spacing across worker restarts, leaving headroom under the current per-user Gmail quota even for raw reads. Local exponential retry is capped at fifteen minutes; a longer provider Retry-After is honored. Permanent permission and reconnect errors pause that mailbox until its credential generation changes. Label catalog refresh clears names missing from the current provider catalog so unresolved privacy metadata denies later AI/index use. The worker schedules bounded blob-intent cleanup and logs only safe status codes.
